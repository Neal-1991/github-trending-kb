## 2. 本次已完成优化

### 2.1 canonical 快照成为真正的每日榜主来源

- 数据库重建优先读取 `data/daily/snapshots/YYYY/MM/YYYY-MM-DD.json`；
- `trends.jsonl` 仅补没有 canonical 的历史日期，不再覆盖同日快照；
- 修复 legacy 回放只返回当天第一条榜单的问题，现在会返回该日全部榜单；
- 加入 schema、日期、榜单唯一性、`entry_count` 与 `snapshot_id` 内容哈希校验；
- canonical 内容被篡改或损坏时 fail closed；
- 历史归档文件名增加微秒，避免同秒多次刷新互相覆盖；
- `trends.jsonl` 改为按日期整批原子同步，重跑可修复中断后留下的部分导出。

### 2.2 dry-run 实现项目文件零副作用

- `--dry-run` 不再替换项目内 SQLite；
- dry-run 在系统临时目录重建派生库，结束后自动清理；
- 不创建项目内 daily/profile/README 目录；
- 不写快照、source、投递日志，也不调用 GLM 或飞书；
- 预览仍写到系统临时目录，便于人工检查。

### 2.3 每日画像和派生索引一致性

- 同一新仓库出现在多个榜单时，所有记录的 `is_new` 保持一致；
- 待画像队列保留“总榜优先、榜内排名优先”的顺序，不再用字母排序破坏优先级；
- 无 GitHub Token 时复用榜单/数据库已有元数据，不再给 GLM 传全空元数据；
- README 为空时跳过 GLM，避免无有效输入的调用和计费；
- 增量写入仓库/画像后重建 FTS，Web 搜索不再等到下次全量 rebuild 才可见；
- 画像输入加入 `input_hash`、`schema_version`、`prompt_version`；
- 相同模型、提示词版本、元数据和 README 重跑时跳过 GLM；
- 画像 source 使用带 flush/fsync 的单行持久化，数据库可从 source 恢复。

### 2.4 README 状态机落地

- `_missing.txt` 改为原子合并，不再只保存“本轮”缺失项；
- 成功获取 README 后可清除旧的永久缺失标记；
- `no_readme` 会写入数据库状态；
- 全量数据库重建会从 `_missing.txt` 恢复状态；
- 已有画像的仓库优先保持 `done`，不会被缺失清单覆盖。

真实数据验证结果：`_missing.txt=1153`，数据库 `profile_status='no_readme'=1153`。

### 2.5 通知恢复与同日刷新语义

- 投递状态按 `(kind, date, snapshot_id)` 查询；
- 同日显式刷新得到的新 snapshot 拥有独立投递状态；
- `daily_doc/weekly_doc=created` 时复用已有文档，不重复创建；
- 链接已发送但最终事件未落盘时，只补记恢复事件，不重复发送外部消息；
- legacy 日报日期与 `week-日期` 改为精确匹配，不再交叉污染；
- `push_log.jsonl` 改为按业务键整批原子合并；
- Actions 通知任务会同时提交 `delivery_log.jsonl` 和 `push_log.jsonl`。

飞书仍属于“至少一次 + 可检测重复”语义：服务端没有业务幂等键，因此无法宣称
exactly-once；所有新事件携带 `snapshot_id` 和 message/document ID 便于审计。

### 2.6 trusted 统计与 Web 一致性

- `core_days` 现在与其他指标一样排除 degraded 观测；
- 仓库详情页的 Top10 曲线只使用 full/partial Top10 数据；
- 趋势季度语言统计排除 degraded 数据；
- sparkline 的数据口径与页面标题统一为 trusted Top10；
- 所有模板内部链接改用 `url_for`，支持挂载到 `/kb` 等 root path；
- 搜索分页使用 URL API 编码和保留查询参数，避免 `&` 等字符破坏链接。

### 2.7 CI、依赖和仓库治理

- 新增 `.github/workflows/ci.yml`；
- CI 顺序为 Ruff → pytest → 只读数据审计；
- 每日抓取在访问外部 API 前运行测试和数据审计；
- Git rebase 失败后显式 abort，避免工作流遗留半完成 rebase；
- 新增 `requirements.lock`，CI 和定时任务统一按锁文件安装；
- Ruff 明确启用基础正确性与导入规则，存量问题已清零；
- `.gitignore` 增加 `*.egg-info/`；
- 删除一份内容完全相同的 Review 文档副本；
- 清理 `glm_client.py` 重复模块说明和存量未使用导入。

## 4. 按规格暂停的 P0 子阶段：稳定仓库身份

2026-09-01 对 ClickHouse 公共 playground 的 `github_events` 执行只读
`DESCRIBE TABLE`，确认该表只有 `repo_name`，没有 `repo.id` 或其他稳定 repository ID。
因此无法按规格从现有 GH Archive 历史重建数据可靠地区分“仓库改名”和“同名复用”。

本次严格遵守迁移约束：

- 没有按名称猜测合并；
- 没有覆盖旧 raw 数据；
- 没有把 API 当前 `repo_id` 倒推到无法验证的历史观测；
- 保留 34 个 `created_at > first_trend_date` 身份异常并持续审计；
- README/Web 明确标注 identity v2 尚未完成。

可继续实施 identity v2 的前提是获得包含历史 `repo.id` 的 GH Archive 原始事件源，
或建立另一条可审计、可重复获取的稳定 ID 映射数据源。取得数据源后再生成 v2 文件、
before/after 计数、未映射列表以及合并/拆分报告。

   消除 capture/notify 静默失败（此前只有 GitHub 站内邮件可感知）。

   容忍损坏旧文件（原样归档后替换），否则自愈路径会在归档前崩溃。

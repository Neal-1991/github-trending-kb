# 操作手册

版本:v1 · 2026-09-06。配套文档:[功能设计文档](功能设计文档.md)。

## 1. 日常使用(只需要记住这一条)

**双击 `restart_web.bat`**,等它自动打开浏览器即可。脚本会:结束旧进程 → 启动新服务(新窗口,标题"GitHub趋势榜知识库",日志在里面) → 等待就绪 → 打开页面。默认端口 8000,需要换端口时执行 `restart_web.bat 8001`。

- 关闭服务 = 关掉那个日志窗口。
- 代码更新后必须重启才生效,重启就用这个脚本,不要手动找 PID 杀进程。
- 服务开着的时候,数据自动保持最新(启动查一次,之后每 30 分钟查一次),不需要每天做任何操作。

## 2. 页面导览

| 页面 | 什么时候用 |
|---|---|
| 首页 | 看库的整体概况、最新真实榜 Top10、最近一周新面孔;顶部有数据新鲜度提示 |
| 检索 | 按名称/描述/画像找项目,支持中文;可用语言下拉和"仅有画像"过滤 |
| 新面孔 | 看最近 N 周(4/8/13/26/52)首次上榜的项目,按周分组 |
| 趋势图谱 | 看季度语言构成、长期上榜的中坚项目、现象级爆发(已排除疑似刷星) |
| 按日浏览 | 看某一天某个榜的完整排名(真实抓取榜/历史重建榜/语言榜) |
| 仓库详情 | 点任意项目进入:元数据、五维画像、星标曲线、排名走势 |

## 3. 同步状态条怎么看(全站顶部)

| 显示 | 含义 | 你需要做什么 |
|---|---|---|
| 正在检查更新…/正在下载数据…/正在校验数据…/正在构建数据库…/正在发布新版本… | 后台同步进行中,按钮显示当前阶段 | 不用管,期间旧数据照常可查 |
| 与 GitHub 已同步 · 数据更新至 X | 没有更新的数据了 | 不用管 |
| 新数据已就绪 · 更新至 X · 刷新查看。 | 新版本已生效 | 点"刷新查看"(当前页面和搜索词都保留) |
| 同步失败:原因。当前仍可查询已有数据。 | 本次同步失败,旧数据可用 | 一般等下一轮自动重试即可;持续失败见第 7 节错误码表 |
| 尚未同步 · 本地数据更新至 X | 服务刚启动还没完成首次检查 | 稍等,或点"立即同步" |
| 自动同步已关闭 | 配置了 `DATA_SYNC_ENABLED=false` | 需要同步时改为 true 并重启 |
| 同步接口不存在:本地服务是更新前启动的,请重启… | 页面是新模板但服务进程是旧的 | 双击 `restart_web.bat` 重启 |

"立即同步"按钮:手动触发一次检查,运行中再点会提示"同步已在进行中"(合并,不会重复下载)。

## 4. 同步与维护命令(命令行)

```bash
python scripts/sync_data.py --once                  # 手动同步一次(成功 0,失败非 0,锁被占用 3)
python scripts/sync_data.py --status                # 查看同步状态 JSON(不触网)
python scripts/sync_data.py --list-generations      # 列出本地数据版本
python scripts/sync_data.py --activate-generation ID  # 回滚:切换到指定版本
python scripts/sync_data.py --build-local           # 离线时用工作区数据构建初始版本
python scripts/build_db.py                          # 重建工作区数据库(传统模式)
python scripts/audit_data.py                        # 数据质量审计
python scripts/daily_job.py --dry-run               # 零副作用预览每日任务(本地体验采集流程)
python -m pytest -p no:cacheprovider                # 全量测试
python -m ruff check .                              # 代码检查
```

首次启动的三种情形(都会自动处理):有本地数据 → 立即可查;都没有但工作区有 source → 先离线建一版再查远端;完全没有 → 显示"正在准备数据"页,完成后自动进入首页。

## 5. 配置项(.env,均可省略)

| 变量 | 默认 | 说明 |
|---|---|---|
| `DATA_SYNC_ENABLED` | true | 自动同步总开关;false 时状态条如实显示"自动同步已关闭",查询不受影响 |
| `DATA_SYNC_REPO` / `DATA_SYNC_BRANCH` | 本仓库 / main | 数据来源(只读) |
| `DATA_SYNC_INTERVAL_SECONDS` | 1800 | 自动检查周期 |
| `DATA_SYNC_TOKEN` | 空 | 可选只读 Token(公共仓库不需要;限流频繁或私有仓库时配置) |
| `DATA_SYNC_MAX_FILE_BYTES` / `DATA_SYNC_MAX_TOTAL_BYTES` | 64MiB / 512MiB | 下载大小上限 |
| `DATA_SYNC_TASK_TIMEOUT_SECONDS` | 900 | 单次同步任务时限 |
| `GITHUB_TOKEN` `GLM_API_KEY` `GLM_MODEL` `FEISHU_*` | — | 云端采集/画像/通知用(本地网页不依赖) |

改完配置需要重启服务生效。

## 6. 回滚(数据版本出问题时)

按顺序选择,任何一步都不需要删除数据:

1. **指回上一个数据版本**:`python scripts/sync_data.py --list-generations` 找到版本 ID,然后 `--activate-generation <ID>`,刷新页面即生效。
2. **停用同步、回到工作区数据库**:`.env` 设 `DATA_SYNC_ENABLED=false` 并重启;需要时再 `python scripts/build_db.py` 重建工作区库。
3. 极端情况:`DATA_SYNC_ENABLED=false` 后整个 `data/runtime/` 可以删除重建,它不含任何独有数据(source 都在 Git 里)。

## 7. 故障排查

### 7.1 同步失败错误码

| 错误码 | 含义 | 处理 |
|---|---|---|
| `NETWORK_ERROR` | 网络不可用 | 恢复网络后自动/手动重试 |
| `RATE_LIMITED` | GitHub 限流 | 等状态里的 next_check_at;频繁发生就配置 `DATA_SYNC_TOKEN` |
| `HTTP_ERROR` | GitHub 返回 4xx/5xx | 看消息里的状态码;404 检查 `DATA_SYNC_REPO/BRANCH` 是否写错 |
| `REQUIRED_FILE_MISSING` / `TREE_TRUNCATED` | 远端提交不完整/清单截断 | 通常是云端正在提交,稍后重试 |
| `SIZE_LIMIT` | 文件超过大小上限 | 数据异常膨胀,检查远端仓库 |
| `HASH_MISMATCH` | 下载内容校验不符 | 传输损坏,重试即可 |
| `INVALID_SOURCE` / `VALIDATION_FAILED` | 远端数据格式/候选库校验失败 | 看具体消息;若因云端坏数据,修复提交后重试 |
| `REGRESSION` | 远端候选数据比本地旧 | 已自动保留新版,无需处理(历史修订场景) |
| `TIMEOUT` | 单次同步超时限 | 调大 `DATA_SYNC_TASK_TIMEOUT_SECONDS` |
| `CANCELLED` | 服务关闭时任务被中止 | 正常现象,下次启动会重新同步 |
| `INTERNAL` | 未预期错误 | 记下消息内容排查 |

### 7.2 常见问题

- **"数据更新至 X"不是今天**:这不是失败——云端 Actions(每天 08:00)还没跑完、失败或确实没有新上榜数据。去 GitHub 仓库的 Actions 页面看当天两个 Job 的状态;失败会有飞书告警。数据到位后本地会在下一轮检查(≤30 分钟)自动跟上,急的话点"立即同步"。
- **页面打开 404/显示"同步接口不存在"**:服务进程是旧代码启动的,双击 `restart_web.bat` 重启。
- **端口被占用(启动报 winerror 10048)**:`restart_web.bat` 会自动结束旧进程;若换过端口,用 `restart_web.bat <端口>`。
- **电脑关机/长期不开机有影响吗**:没有。采集在云端跑,本地只要下次开机启动服务,启动检查会一次性追上全部已提交的数据(缺失的多天数据一起到位)。
- **同步期间页面卡吗**:不卡。下载和建库在后台线程,旧数据版本持续可查;发布是新版本原子切换。
- **想立即拿到最新数据**:点状态条"立即同步",或命令行 `python scripts/sync_data.py --once`。

## 8. 数据与安全边界(了解即可)

- 同步器只读 GitHub,不做任何 Git 写操作,不修改工作区代码和受 Git 管理的数据;所有本地同步产物在 `data/runtime/`(已 gitignore)。
- 同步库与 Actions 构建的库同源同口径;任何校验失败(内容哈希、快照寻址、数据库完整性、日期一致性)都不会发布,旧版本继续服务。
- Web 服务默认只监听本机回环地址,写接口有 Host/Origin/CSRF 三重校验;没有部署公网的能力,也没有公网暴露的风险面。

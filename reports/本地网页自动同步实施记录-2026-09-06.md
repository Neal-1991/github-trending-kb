## 阶段 2:同步核心与 CLI

`scripts/sync_data.py`:

- 一次同步固定在 HEAD commit:解析 SHA → git tree(截断则 BFS 补齐,仍截断报 `TREE_TRUNCATED`)→ 全部文件按该 SHA 下载。
- 白名单:5 个必需文件 + canonical 快照(至少一份)+ 可选覆盖规则/push_log/归档;其余一律忽略(代码、README 缓存、history、远端 SQLite、.env 均不入)。必需缺失即失败保留旧版;HTTP 错误不当作"可选不存在"。
- 下载走 api.github.com blob(公共仓库免 Token;`DATA_SYNC_TOKEN` 可选,仅入该域名请求头);Git blob sha1(`blob <len>\0` 前缀)校验 + 内容 sha256 记入 manifest;单文件/整批大小上限。
- 缓存复用:blob sha 未变时从上一 generation 复制,并复验 sha256,不符即重新下载,不盲信缓存。
- 校验链:CSV/JSONL 完整解析、覆盖规则可解析、canonical 快照内容寻址校验、`integrity_check`/必需表/FTS 行数、无未来日期、库内最新日期与 source 一致、首页统计/检索/最新日榜单抽样查询、当前库已有真实榜时候选不得倒退(`REGRESSION`)。
- 发布:staging 整体移入 generations(不覆盖被占用的 SQLite 文件)→ 原子写 active.json → 清理老版本;发布前设取消点,退出中的任务不发布新指针。
- 状态模型:phase/last_result/last_checked_at/last_success_at/last_updated_at/remote_commit/active_commit/active_generation/active_latest_date/last_error_code/next_check_at;失败保留旧库信息,错误落状态不吞掉;限流尊重 `Retry-After` 写入 next_check_at。
- 更新判断:fingerprint(路径+blob sha+大小)与 build_version 都不变 → up_to_date(不下载不重建);commit 变数据没变 → 只更新检查信息;同日画像/元数据变化 → 照常重建。
- CLI:`--once`(0/1/3 退出码)、`--status`、`--list-generations`、`--activate-generation`(受锁保护的回滚维护命令)、`--build-local`。

## 阶段 3:后台与页面

- `web/sync_service.py`:协调器单线程循环,启动即查一次、按周期检查、手动触发合并到现有任务;网络/下载/建库全部在工作线程;`stop()` 通过取消点安全中止,有限等待。
- `web/app.py`:lifespan 启停协调器(config 开关调用时读取);`GET /api/sync/status` 只读本地状态不碰库不触网;`POST /api/sync` 异步触发 202,Host 白名单(127.0.0.1/localhost/::1)+ 同源 Origin + 进程内随机 CSRF token 三重校验;缺库时 HTML 渲染 `preparing.html`(503),JSON API 保持结构化错误;CSP 显式补充 `script-src 'self'; connect-src 'self'`。
- 页面:base.html 状态条(数据更新至 X/检查/下载/校验/建库/发布/已是最新/更新完成/同步失败文案);`web/static/sync.js` 轮询只打本地 status(运行 2s/空闲 30s/隐藏暂停),动态文本全部 textContent,更新完成给"刷新查看"按钮(保留 URL),不自动刷新页面;准备页完成后自动进入首页(计划允许的场景)。

## 保留的边界

- 自动同步依赖 GitHub Actions 先完成数据提交;本地同步器不抓榜、不补数据,因此"远端也没更新"时页面如实显示"与 GitHub 已同步,数据截至 X",不视为失败。
- v1 保留当前与上一版 generation,更老的延后清理;Windows 上旧读句柄导致的删除失败只跳过重试。
- 同步版本的 `profile_status` 无 no_readme 状态(无 README 缓存),页面检索不使用该字段,展示无差异。
- 30 分钟周期为默认配置,可用 `DATA_SYNC_INTERVAL_SECONDS` 调整;关闭 `DATA_SYNC_ENABLED` 后状态条如实显示"自动同步已关闭"。

## 回滚

1. 关闭同步保留查询:`DATA_SYNC_ENABLED=false`(查询继续使用当前 active 或工作区库)。
2. 指回已验证版本:`python scripts/sync_data.py --activate-generation <id>`(先 `--list-generations` 查看)。
3. 恢复工作区数据库模式:`DATA_SYNC_ENABLED=false` + `python scripts/build_db.py`。
不需要删除 data/runtime;任何情况下都不要以"删库"作为回滚步骤。
